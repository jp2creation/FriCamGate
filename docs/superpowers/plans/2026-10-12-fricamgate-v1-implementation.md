# FriCamGate V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build FriCamGate V1 as an installable Android APK that lets each user connect to their own Frigate server and view cameras, events, and a camera detail timeline.

**Architecture:** FriCamGate is a direct Frigate client built with React, TypeScript, Vite, and Capacitor Android. The app keeps Frigate API access, session storage, data mapping, and UI components separated so authentication and private camera data stay isolated from visual presentation.

**Tech Stack:** React, TypeScript, Vite, Capacitor Android, Vitest, React Testing Library, lucide-react, Android secure storage through a Capacitor secure storage adapter.

**Spec:** `docs/superpowers/specs/2026-10-12-fricamgate-v1-design.md`

## Global Constraints

- App name is `FriCamGate`.
- Target platform is Android phone and tablet.
- V1 is a direct Frigate client; no central FriCamGate backend.
- Each user enters their own Frigate server URL and credentials.
- Default server field is blank in reusable builds; `https://frigate.example.com` is used only as an example in tests and docs.
- Approved logo master is `assets/brand/fricamgate-logo.png`.
- No password, JWT, cookie, signing key, `.env`, or Frigate secret may be committed or bundled in the APK.
- Require HTTPS for normal setup; HTTP is allowed only through an explicit insecure setting with warning text.
- Store session material in Android secure storage, not ordinary local storage.
- Do not copy camera.ui branding, logo, icon, or exact assets.
- V1 must keep cameras usable with latest-frame refresh when live playback fails.
- Source, logs, tests, and diagnostics must redact tokens, cookies, Authorization headers, and passwords.
- Use ASCII text in source files unless a generated Android file requires otherwise.
- If `/usr/bin/git` is blocked by the Xcode license on this Mac, pause commits until the user accepts the license in Terminal.

## Review Focus

- User enters malformed, blank, trailing-slash, HTTP, or whitespace-padded server URL: Task 3 tests URL normalization and rejection.
- User provides wrong credentials or session expires: Task 5 tests login failure and restore failure routing.
- Frigate user has viewer or custom role rather than admin: Task 4 and Task 6 tests avoid admin-only assumptions and show permission states.
- Live streaming fails, buffers, or is unsupported externally: Task 7 tests latest-frame fallback.
- Secrets appear in logs, diagnostics, source, or APK assets: Task 3, Task 5, and Task 8 add redaction and artifact checks.
